# Node + Playwright test-execution migration

DeepContext: project `casinoplanet`, workset `node-playwright-migration`, spec artifact `019fb909-4192-71d9-8cd0-b172d64808d8`.

## Problem
Test execution is homegrown Python driving Chrome by hand. Three structural defects, all previously proven on this repo:
1. `run_integration_tests.py` cannot fail: it polls for `test_report.md` and greps for the substring "Detailed Step Logs", which `test_runner.html` writes unconditionally. 31 failing cases exit 0. It also hardcodes Windows Chrome paths and `sleep(2)` startup waits.
2. `tools/verify/cdp.py` is a 473-line hand-rolled CDP client over hand-framed RFC 6455 WebSockets — per the salvage-scout record it is the fourth such harness written for this repo; the earlier three were mutually incompatible and survive only in the salvage snapshot outside the repo. Cost measured in millions of tokens.
3. `package.json` is dishonest: vite scripts nobody uses, a `ws` dependency nothing imports (verified: no `WebSocket`/`ws` references in `src/`).

## Approach
Adopt `@playwright/test` as the sole test-execution engine. Playwright replaces the transport (CDP), lifecycle (Chrome launch/teardown), and readiness (auto-wait, polling) layers wholesale. Game-specific knowledge — the valuable part of `tools/verify/game.py` — ports to a Playwright helper module. The in-browser suite in `test_runner.html` is instrumented, not rewritten.

## Deliverables

### D1. Node test stack
- `@playwright/test` as a devDependency; Playwright-managed Chromium via `npx playwright install chromium`. Fallback documented in config: `executablePath: /usr/local/bin/chrome` (Chrome 150 installed on buildbox). Launch flags include `--disable-gpu` (GPU rendering unmeasurable on this box — accepted, pre-existing limitation).
- `playwright.config.js` with a `webServer` block that starts `python3 serve.py` (`python` does not exist on buildbox — only `/usr/bin/python3`) and health-checks `http://127.0.0.1:8000/` before tests run (no fixed sleeps). Note: `serve.py` auto-increments its port when 8000 is busy while the config URL is fixed — config must set `reuseExistingServer: false` and treat a busy port 8000 as a hard error, or pass an explicit port if `serve.py` grows a flag. Resolve at plan time; the invariant is: the URL Playwright targets is provably the server this run started.

### D2. Results bridge in test_runner.html
- `runTestCase()` additionally records each case into `window.__testResults = { done: boolean, cases: [{name, status: 'pass'|'fail', message}] }`, set `done: true` after the final case. The existing markdown/`/save_report` path stays untouched for manual browser runs.
- `tests/integration.spec.js`: navigates to `test_runner.html`, waits on the `done` predicate (generous timeout — suite currently needs up to ~200s), then asserts per-case inside `test.step()` so every failing case is named in the report and any failure fails the run. Also attaches a `pageerror`/console-error ledger.
- Case-count ground truth: `test_runner.html` has 11 `runTestCase` call sites, one of which loops over the 21-entry `minigames` array — 31 runtime cases total (matching the 31-row summary table in the committed `test_report.md`). `done: true` is set by the enclosing IIFE after the last case (`runTestCase` itself cannot know finality). Per-case assertions are driven by the runtime `cases` array — no exact-count assertion — BUT the spec asserts a hardcoded FLOOR: `cases.length >= MIN_CASES` with `MIN_CASES = 31`, ratcheted upward when cases are added and never quietly lowered. An exact count breaks on every legitimate addition (iteration-1 defect); no floor lets the suite silently shrink toward green (the exact failure mode this migration exists to kill — and the same distinction the Python toolkit drew with its `MIN_LIMITS` floor, "so limits can be added but not quietly dropped").

### D3. Game helper module (`tests/helpers/game.js`)
Port of `tools/verify/game.py` observation logic onto Playwright primitives, preserving the observations-not-verdicts principle (helpers return records; callers write assertions):
- boot-by-polling (clientInstance → sim.isRunning predicates, never sleeps)
- grid observation + `cell_to_point`/`point_to_cell` reproducing the transform in `game.py:201-225`: `clientInstance.cellSize`/`offsetX`/`offsetY` composed with the canvas bounding rect, guarded by the same `attrW === rectW` scale precondition (throw on mismatch); grid-shape resolver that throws rather than falling back to hardcoded 24×16
- hit-test via `elementFromPoint` with a null-guarded `want.contains(el)` check, as in `game.py:236` — `Node.contains()` covers self-or-descendant, which is the property that makes a hit on a button's inner span count as hitting the button
- `click_cell` with mouseMoved-first ordering; `tap_cell` as back-to-back `touchStart`/`touchEnd` with no inter-event delay, mirroring `game.py:296-305`
- capture-phase event counters (distinguish "never fired" from "handler no-op'd")
- `act()` with precondition checks; `find_legal_cell`; `sim_progress` window observation; exception ledger via Playwright `pageerror`
- `sim_progress` disclosure: its measurement window is an INTENTIONAL fixed duration (it samples sim-state deltas over an interval; the Python original spells this `sess.wait_for("false", window)` — a full-window wait by design, not a readiness sleep). Ported as one named helper, `elapsedWindow(ms)` (deadline predicate via `waitForFunction`), which is the single permitted fixed-duration call site in the harness. It is disclosed here precisely so it is not a grep-evading sleep: any other fixed-duration wait, however spelled, violates SC3's intent even if the pattern misses it.

### D4. Selfcheck with a negative control
The repo's proven failure mode is verification code that silently degrades to always-green. The Node harness ships with:
- `npm run test:selfcheck`: runs the Playwright suite against a copy of `test_runner.html` mutated so one known case must FAIL, and asserts the exit code is non-zero and the failing case is named. This is the direct kill of the "31 FAIL exits 0" class. Mechanism invariant (exact mechanism resolved at plan time): the mutated copy must run in an environment equivalent to the real run — same served root, working relative paths to `src/` and `style.css`, working `/save_report` origin. A bare file copied to scratch does not satisfy this; a sandbox tree (git worktree/archive, as `static.py::sandbox` already does) or an in-place serve of an overlay does.
- Known-answer spotchecks for the geometry helpers (round-trip cell→point→cell).
- Observation/verdict separation on the JS side is enforced, not convention: `tests/helpers/` must not import `expect` from `@playwright/test` (helpers return records; specs assert). Encoded as a static check inside `test:selfcheck` (a `git grep` tier is sufficient — the same ratchet-not-a-sound-gate standard the Python toolkit's README established: it catches the idiomatic spelling a cooperating author would write, not a deliberate bypass).

### D5. Deletions and package.json honesty
- Delete: `run_integration_tests.py` and the ENTIRE `tools/verify/` package — cdp.py, game.py, errors.py, static.py, scan.py, selfcheck/, examples/, hooks/, README.md.
- Why wholesale rather than surgical: the package's selfcheck (`selfcheck/run.py`) is structurally entangled with the browser modules — a hardcoded A/B/C coverage ledger (`run.py:61-63`) that exits 1 on any uncovered item, shared browser fixtures spanning ~lines 271-474/849-966/1507-1551, 8.3/8.4 sections that execute and source-assert `examples/reference_check.py` (which imports cdp and game), and assertions against README.md's own text. Keeping the browser-free members (static.py, scan.py) would require structurally rewriting run.py, ITEMS, the examples, and the README just to keep a ratchet green for ~950 lines of helpers that nothing outside the package consumes (verified: `git grep` finds zero references to `tools.verify`/`tools/verify` outside the package). That is churn spent preserving scaffolding for deleted code. The package's DISCIPLINES — observation/verdict separation, known-answer spotchecks, negative controls, ratchet-not-gate honesty — carry over to the Node harness via D4; the code does not. If a build-reproducibility or sandbox observation is wanted later, it is a dozen lines against `git worktree` + hashing, cheaper to rewrite than the orphaned package is to maintain.
- Keep untouched (Python): `serve.py`, `build_single_file*.py`, `tools/check_id_contract.py` + `tools/id_contract_waiver.json` (verified stdlib-only imports, no `tools.verify` dependency). `tools/__init__.py` is kept as harmless (`check_id_contract.py` runs as a script and does not import the `tools` package; nothing depends on the file either way).
- `package.json`: remove vite scripts + vite devDependency + `ws`; add `test` (playwright) and `test:selfcheck` scripts. `npm test` becomes the single canonical entry point; CLAUDE.md repo-specifics updated accordingly.
- `test_report.md`: removed from git tracking and gitignored (it is dirtied by every run; the Playwright HTML/line reporter replaces it as the record). `playwright-report/`, `test-results/`, `node_modules/` gitignored.

## Out of scope
- Rewriting the in-browser cases (11 `runTestCase` sites / 31 runtime cases) as native Playwright specs (follow-up, case-by-case; new tests SHOULD be native specs from now on).
- The perf/profiling stack (Lighthouse, tracing) — unblocked by this, not built by it.
- mobile touch input, arcade fixes, or any game-code change beyond the test_runner.html instrumentation.
- bun/deno or Node upgrades — declined; Node 22 is Playwright's first-class tier.
- Migrating the build scripts (`build_single_file*.py`) or `serve.py` to Node — DECLINED, not forgotten, resolving the original "buildout and testing" question: testing moves because it is iterated and ecosystem-exposed; the build/serve glue is stdlib-only, working, and ~170 lines with no ecosystem gradient against it. Revisit only if it grows (e.g. if minification/source-maps ever land, that work goes to Node per the project decision).

## Constraints
Observations-not-verdicts separation carries over: helper modules return records, assertions live in specs. No fixed sleeps anywhere in the NEW harness code (`playwright.config.js`, `tests/**`) — every wait is a predicate poll (`waitForFunction`/`expect.poll`) or Playwright auto-wait; the Python originals' `settle` waits are wait-for predicates (`game.py:465`), so no readiness sleep may be introduced. The single intentional fixed-duration construct is `sim_progress`'s measurement window (`game.py:518` runs its full window by design), carried over solely as D3's disclosed `elapsedWindow()` helper. `test_runner.html`'s pre-existing internal `setTimeout` pacing is out of scope and unchanged. Manual flow (open test_runner.html in a browser, report POSTs to serve.py) keeps working. Single-file builds and their committed artifacts unchanged. Must run headless on buildbox with --disable-gpu. The migration touches no game logic; the only src-adjacent change is the results object in test_runner.html.

## Success criteria
1. `npm test` runs the full suite (all `runTestCase`-derived runtime cases, driven by the runtime `cases` array) headless on buildbox and exits 0 when green, and asserts the `MIN_CASES = 31` floor — mutating `test_runner.html` to run fewer than 31 cases must fail the run.
2. Sabotage test: forcing any single case to fail makes `npm test` exit non-zero and name the case — run once manually AND encoded permanently as `npm run test:selfcheck`.
3. `git grep -nE "waitForTimeout|\bsleep\b|setTimeout\([^,)]+,\s*[0-9]+" -- playwright.config.js tests/` returns zero hits (note: the pattern matches comments too — word comments accordingly). The sole sanctioned fixed-duration construct is `elapsedWindow()` per D3's disclosure, implemented so it does not match the pattern and permitted at exactly one call site (`sim_progress`).
4. After deletion, `git grep -n "tools.verify\|tools/verify\|run_integration_tests"` returns hits only in `docs/specs/` (this document, which IS committed as part of this work per the methodology's committed-design-doc requirement) — no dangling references in code, config, or CLAUDE.md.
5. Both build scripts still exit 0, and `python3 tools/check_id_contract.py` reports an exit status and problem set UNCHANGED from main. (Baseline-relativized by user decision 2026-07-31 after plan-review execution proved the checker exits 1 on untouched main — pre-existing mobile scorecard gaps: five unwaived tier-2 ids plus a tier-1 unguarded deref at `ClientGame.js:1380`, owned by the mobile-playability effort. This migration must not alter the checker's output; it need not — and may not — fix the underlying gaps.)
6. `package.json` lists no script or dependency that is not actually used.
7. git status clean after a full `npm test` run (no tracked file dirtied).
